# M5 – States & layouts

Goal: koje remembers and restores the work environment.

- [x] **M5.1 Capture**: running windows of a context → `State` (window IDs, commands, geometry)
  - Done (host-tested 2026-10-20), ADR 0030: kojed's live state per context (`koje_core::capture::Live`; ids from integration or app id + counter), specs from `/proc` (`kojed::procfs`), D-Bus `State(context)`, `koje save <context> [-s <state>]` (the save half of M5.4).
- [x] **M5.2 Integrations**: file format, loader, built-ins `generic`, `terminal`, `editor`, `devcontainer`, `browser`
  - Done in code, ADR 0031: `koje_core::integration` (TOML, `detect` = `argv-last` / `cwd` / `shell-cwd`), built-ins terminal/editor/browser, user files in `~/.config/koje/integrations/`. Launching: M5.3. `devcontainer` with dev container windows in states moved to M9.1.
- [x] **M5.3 Restore on `up`**: resolve state, launch windows, match new windows to IDs, place them
  - Done (host-tested 2026-10-20: foot in its cwd, Firefox with 3 windows, nautilus, all in place): `koje up` resolves (requested → `fresh` → `empty`) and sends the state to kojed (`Restore`); `koje_core::restore::plan` (launch templates, `cwd`, `launch_once`), `ContainerRuntime::launch`, matching by app id in `Live::add`, placement from the active layout, 60 s expiry. Not yet: stash for windows outside the active layout (M5.5), dev container windows.
- [x] **M5.4 `down` / `save` with `-s`**, ordered window close
  - Done (host-tested 2026-10-20; Firefox 158 quits cleanly on SIGTERM, reopens its windows with "Open previous windows and tabs"): `koje down [-s]` saves first, then kojed ends the programs (`CloseWindows`: close windows, or SIGTERM per process for `quit = "signal"`), waits up to 10 s for the windows and the signalled processes (Firefox writes its session after closing its windows – first host test showed the restore prompt), asks before stopping if something stays; without kojed it stops directly (`--no-save`) or refuses (would lose the state).
- [x] **M5.5 Layout switching** using `plan_switch`; stash as special workspace; focus handling
  - Done (host-tested 2026-10-21): `koje_core::live_layouts` (switch/next/prev/new/save on the live state, the active layout keeps its arrangement if it autosaves), per-context stash `special:stash-<context>`, D-Bus `SwitchLayout`/`NewLayout`/`SaveLayout`/`SetLayoutAutosave`/`RenameLayout`/`RemoveLayout`/`Layouts`, `koje layout …` (default: the active context), Super+[ / Super+]. Restored windows outside the active layout go to the stash. Focus handling: not yet (last active window per layout).
- [x] **M5.6 `stash` / `unstash`**; new/closed windows update layouts
  - Done (host-tested 2026-10-21): `koje stash [--show]`, `koje unstash [<window>] [--to <layout>]` (D-Bus `Stash`/`Unstash`/`ToggleStash`), Super+H / Super+Shift+H / Super+Ctrl+H; new windows join the active layout, closed ones leave all (M5.1).
- [x] **M5.7 Autosave** of geometry changes into the active layout (debounced)
  - Notes: M2.2 – no event for moving/resizing floating windows; re-read `j/clients` on focus changes / debounced and diff.
  - Done (host-tested 2026-10-21): kojed takes each running context's live state every 5 s (`Daemon::tick`): the active layout (if autosave) follows moved/resized windows; the file manager is asked only when a title changed.
- [x] **M5.8 Crash recovery**: continuous recovery file; `up` prompt, `--recover`/`--no-recover`
  - Done (host-tested 2026-10-21), ADR 0006: the tick writes `recovery.toml` when the state changed; a clean `down` deletes it; `up` of a stopped (or windowless) context with a recovery file asks (default yes), `--recover`/`--no-recover` decide, without a terminal it is kept; a restarted kojed takes running contexts' live states from their recovery files (ids, layouts kept).
- [x] **M5.9 State switching in a running context** (uses M1.9)
  - Done (host-tested 2026-10-21): `koje up <context> -s <state>` on a running context saves into `default` (unless `--no-save`), then kojed (`SwitchState`, `Live::switch_state`) keeps windows by id, closes the rest (SIGTERM only if a program's every window goes; a window asking to save stays until it closes), starts the missing ones and arranges by the target's active layout. Without `-s`: "already running". Host test: after `-s empty` the next `up` asked to recover (the recovery file still had the old windows, and "running without windows" counted as a crash) – fixed: kojed writes the file for empty contexts too and reports `WindowsLost` only when a restarted kojed finds none of a recovered state's windows. Second finding: `up -s default` after `-s empty` saved the empty windows into `default` – ADR 0032: kojed remembers the current state; save, down and the save before a switch write it (none for `empty`, then `default`).

- [x] **M5.12 File manager windows reopen in their folders** (wish, 2026-10-20): Nautilus runs one process for all windows, so `/proc` cannot tell a window's folder. First check on the host that the property lists every window's folder.
  - Done (host-tested 2026-10-20: two windows reopen in Home and Downloads, in place; only the active tab comes back): built-in `files`, detect `file-manager` (ADR 0031), `ContainerRuntime::query`; the property lists every tab, the title picks the active one.
