# M2.4 – Filtered D-Bus

- Date: 2026-10-17
- Host: Ubuntu 26.04 LTS, GNOME (host session bus), xdg-dbus-proxy (Ubuntu package), Hyprland v0.53.3 nested

## Question

Programs in a context use the context's own session bus (ADR 0015). Can selected
host services – notifications, the file chooser portal – be reached through a
forwarder in the context and a filtered proxy of the host bus, while everything
else (in particular `OpenURI` on the host) stays unreachable? Which other
interfaces should be allowed (screen sharing for video calls, secrets)?

## Setup

- Host: `docs/spikes/setup/host-bus-proxy.sh a` – `xdg-dbus-proxy --filter` with
  `--talk=org.freedesktop.Notifications`, `--call` for `FileChooser.*`,
  `Request.*` and `Properties.Get` on the portal, `--broadcast` for
  `Request.Response`. Socket in a mounted directory.
- Context: `KOJE_SPIKE_HOSTBUS=1 run-context.sh a wayland-1`; forwarder
  `docs/spikes/setup/bus-forward.py <name> $KOJE_HOST_BUS` per name.
- Prototype check in the dev container (two local buses, fake notification
  service): call forwarded, reply returned, `NotificationClosed` re-emitted on
  the context bus – works.

## Result

| Check | Result | Notes |
|---|---|---|
| `notify-send` in the context → notification on the host desktop | **works** | forwarder: `GetServerInformation`, `Notify`; proxy: returns from `:1.32` (GNOME) |
| Notification actions / closed signal back in the context | not tested on the host | worked in the dev container prototype (`NotificationClosed`) |
| `OpenURI` on the host via the proxy | **denied** | `org.freedesktop.DBus.Error.AccessDenied`; proxy log `C3: -> org.freedesktop.portal.Desktop call org.freedesktop.portal.OpenURI.OpenURI … *DENIED*` |
| In-context xdg-desktop-portal | gets D-Bus activated on the context bus | Fedora's image ships it; a call to `org.freedesktop.portal.Desktop` on the context bus started it ("No such interface FileChooser"). The forwarder must own the name first, or the image must not activate it |
| File chooser portal via forwarder: dialog appears on the host | **works** | `gdbus` needs typed args (`"@a{sv} {}"`): the proxy denies `Introspect`. Handle `/org/freedesktop/portal/desktop/request/1_5880/t` |
| Chosen path usable in the context (same-path mounts only) | by design | the portal sees the proxy as a host program and returns host paths |
| `Request.Response` signal reaches the context (forwarder log) | **yes** | request path contains the proxy's unique name (`1_5880`), one per context |
| Firefox with `widget.use-xdg-desktop-portal.file-picker = 1` | not tested | |

## Conclusion

The own-bus-plus-forwarder design works: notifications and the file chooser
reach the host, `OpenURI` does not, and replies and signals come back. Recorded
as [ADR 0019](../decisions/0019-host-interfaces-via-forwarder.md).

- Allowed by default (access switches, ADR 0017): notifications, file chooser,
  settings (read-only), inhibit, screen sharing, print.
- Secrets: own keyring per context; selective sharing is an open question.
- The image's own `xdg-desktop-portal` gets D-Bus activated on the context bus;
  the forwarder must own the portal name first (or the image disables it).

ADRs / plan changes / open questions:

- ADR 0019; ADR 0017 extended with six switches (M1.13).
- *D-Bus filter* settled; new: sharing secrets, files outside mounts.
- New M2.10 (settings, inhibit, screen sharing incl. fd passing, print through
  the forwarder) and M3.14 (proxy + forwarder per context).
