## Question

Can koje-shell show a picture of every window in the overview (ADR 0049)
through Hyprland's `hyprland_toplevel_export_v1` – also windows on hidden
workspaces, in a context's stash (special workspace) and of a paused context –
and how long does a capture take?

## What the source says (Hyprland 0.53.3)

- `capture_toplevel` takes the low 32 bits of the window's address; a frame
  fails for an unknown or unmapped window. Windows on hidden and special
  workspaces stay mapped.
- With `copy(…, ignore_damage = 1)` the window is rendered offscreen at once
  (`renderWindow` into the buffer) – it does not wait for the window to be
  shown or to draw a new frame. A paused context's window keeps its last
  buffer.
- The buffer is offered as shm in the renderer's preferred read format, which
  follows the monitor (8 or 10 bits per channel), and as dmabuf.
- More than three frames in half a second make Hyprland report the client as
  a screencast (`screencast` IPC event).
- Clients on a security-context socket (contexts, ADR 0022) do not get the
  protocol (M2.9); koje-shell runs on the host's socket.

## Setup

The package from `just deb` (from commit with M8.67's capture code), installed
with `just install`, in the koje session. Some windows: a few on the current
workspace, one on another workspace, one stashed (`koje stash`), and windows of
a paused context (`koje sleep <context>`).

```sh
mkdir -p /tmp/thumbs
koje-shell capture-probe /tmp/thumbs
```

It prints one line per window: captured or failed, the size and pixel format,
the time to capture and to scale down; with the directory it writes each
thumbnail as a PPM image there (`eog /tmp/thumbs/*.ppm`).

Then the overview itself: Super, look at the cards.
