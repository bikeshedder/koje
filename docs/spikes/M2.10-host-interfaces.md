# M2.10 – More host interfaces through the forwarder

- Date: 2026-10-17
- Host: Ubuntu 26.04 LTS, GNOME, xdg-dbus-proxy, Hyprland v0.53.3 nested

## Question

Do the further host interfaces of ADR 0019 – settings, inhibit, screen sharing,
print – work through the filtered proxy and the forwarder? Screen sharing needs
file descriptors (PipeWire remote) to pass through the forwarder.

## Setup

As M2.4, with the extended filter in `docs/spikes/setup/host-bus-proxy.sh`.
Prototype check in the dev container: a reply carrying a file descriptor passes
the forwarder and is readable by the client – works.

## Result

| Check | Result | Notes |

## Conclusion

Settings, inhibit and screen sharing work through the filtered proxy and the
forwarder; the file chooser works for GTK apps with `GTK_USE_PORTAL=1`. Three
things were needed beyond M2.4:

- **Proxy filter:** allow `Properties.GetAll` and `Introspect` on the portal
  object (GDBusProxy clients treat a denied `GetAll` as "no portal"); wildcards
  only as `Interface.*`; `host.portal.Registry.Register` stays denied.
- **Forwarder:** one host connection per client, and translation of the name
  segment in request/session paths (object paths and message bodies). Without it
  clients that predict their request path (libwebrtc) never see the `Response`.
  Filters run on GDBus' worker thread – no blocking calls there.
- **Context environment:** `XDG_SESSION_TYPE=wayland` (libwebrtc) and
  `GTK_USE_PORTAL=1` (GTK file chooser via portal).

Printing via the portal does not help Firefox (GTK's own dialog in the context);
`print` now means the host's CUPS socket (ADR 0019).

ADRs / plan changes:

- ADR 0019 (forwarder design, printing via CUPS), ADR 0015 (two variables).
- M2.11 for the remaining checks; M3.14 notes.
