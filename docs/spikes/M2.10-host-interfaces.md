# M2.10 – More host interfaces through the forwarder

- Date: 2026-10-17
- Host: Ubuntu 26.04 LTS, GNOME, xdg-dbus-proxy, Hyprland v0.53.3 nested

## Question

Do the further host interfaces of ADR 0019 – settings, inhibit, screen sharing,
print – work through the filtered proxy and the forwarder? Screen sharing needs
file descriptors (PipeWire remote) to pass through the forwarder.

## Setup

As M2.4, with the extended filter in `docs/spikes/setup/host-bus-proxy.sh`.
Prototype check in the dev container: a reply carrying a file descriptor passes
the forwarder and is readable by the client – works.

## Result

| Check | Result | Notes |
|---|---|---|
| Proxy restarted while forwarders run | forwarders break | every call: "The connection is closed"; the prototype does not reconnect. The real forwarder must reconnect (or be restarted with the proxy) |
| `Settings.ReadOne org.freedesktop.appearance color-scheme` | **works** (`uint32 1` = dark) | first filter `--call=…Settings.Read*` was denied: wildcards only as `Interface.*`; now `Settings.*` |
| `SettingChanged` reaches the context when dark mode changes on the host | | |
| `Inhibit.Inhibit` – listed by the host session manager | **works** (GNOME inhibitors 4 → 5) | flags must be `uint32` |
| Inhibit released when the caller exits? | | the host sees the proxy as caller |
| `Print.PreparePrint` – host print dialog | accepted (request handle `…/request/1_5976/pr1`) | dialog? |
| Firefox's print dialog | GTK's own dialog **in the context**, no printers | Firefox does not print via the portal (also with `GTK_USE_PORTAL=1`); the context has no CUPS access |
| Firefox ↔ portal after allowing `Properties.GetAll` + `Introspect` | talks to the portal | `GetAll`, `Settings.ReadAll`, `Inhibit.Inhibit` answered by the host portal |
| `org.freedesktop.host.portal.Registry.Register` (Firefox) | denied, kept denied | lets a host app claim an app ID; a context could claim any app's ID and its permissions |
| Screen sharing in Firefox (gum_test, *Screen*): host picker, preview shows the window | only tabs offered | `XDG_SESSION_TYPE` unset: libwebrtc assumes X11. With `XDG_SESSION_TYPE=wayland`: "Use operating system settings" appears |
| `ScreenCast.CreateSession` through the forwarder | portal answers, nothing follows | `Response` goes to `…/request/1_5985/<token>` (the forwarder's host name); Firefox listens on the path built from *its* context bus name |
| Forwarder with one host connection per client + path translation (dev container, fake portal) | works | Response on the predicted path, `session_handle` translated, fd from `OpenPipeWireRemote`, `Close` translated back; host connection closed when the client exits |
| Screen sharing with the new forwarder | | |
| Firefox file picker via portal | **works** with `GTK_USE_PORTAL=1` | "Save Page As…" opens the host's dialog |
