# M2.6 – Memory sharing between contexts

- Date: YYYY-MM-DD
- Host: Ubuntu 26.04 LTS, kernel 7.0.0-38-generic, RAM …, Podman 5.7.0

## Question

Do two contexts from the same base image share library pages (e.g. of the
browser)? Does a context's cgroup memory include its nested containers?

## Setup

Two contexts `koje-spike-a`, `koje-spike-b` from `localhost/koje-spike/base`,
Firefox in each with the same pages open. Baseline: two Firefox profiles in *one*
container (the host's Firefox is a Snap, so it is not a fair comparison).
Measured with `docs/spikes/setup/mem.sh` and `cgroup-mem.sh` after ~1 min idle.

Note: "shared" also counts pages shared between the processes of *one* Firefox
(binary, libxul). Cross-context sharing shows as a rise of a's PSS when b's
Firefox is closed. Page cache is charged to the cgroup that first read a page,
so `memory.current` of a and b can differ for the same workload.

Observations so far:

- Page cache stays charged to a context after its programs exit (b: 221 MiB
  file pages with no process left). It is reclaimable, but counts in
  `memory.current` – relevant for soft/hard limits (M6).
- First-touch charging: the same workload shows 800–840 MiB in b and 840–870 MiB
  in a.
