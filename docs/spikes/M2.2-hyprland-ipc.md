# M2.2 – Hyprland IPC from Rust

- Date: YYYY-MM-DD
- Host: Ubuntu 26.04 LTS, kernel 7.0.0-38-generic, Hyprland v0.53.3 (nested in GNOME)

## Question

Can koje list, move and color windows and follow window events through
Hyprland's sockets from Rust, and is one batched request fast enough for layout
switches? This decides the shape of the `Compositor` port.

## Setup

`docs/spikes/setup/hypr-ipc` (std + serde_json), Hyprland nested in GNOME with
`docs/spikes/setup/hyprland-nested.conf`.

## Result

| Check | Result | Notes |
|---|---|---|
| `hyprland-nested.conf` accepted as is (version: `hyprctl version`) | no | `windowrule = float, class:.*` → "invalid field float: missing a value"; new syntax `windowrule = match:class .*, float on` |
| Notices when nested | harmless | `XDG_CURRENT_DESKTOP` inherited from GNOME (set it to `Hyprland`), no `start-hyprland`, no `hyprland-guiutils` |
| `hypr-ipc clients`: address, pid, workspace, position, size, class, title | works | `j/clients` gives all of them; context windows (foot, Firefox) appear in the nested Hyprland. `hyprctl` from a GNOME terminal needs `HYPRLAND_INSTANCE_SIGNATURE` |
| `pid` of a window from a context = host PID of the program in the container | yes | `/proc/<pid>/cgroup` → `…/libpod-<container id>.scope/container` |
| `hypr-ipc move` moves + resizes exactly | ok | batch reply: one `ok` per command |
| `hypr-ipc color`: which syntax works, does the color stick (focus change, new window) | none of the pre-0.53 syntaxes | `dispatch setprop … activebordercolor/bordercolor` → "prop not found"; `setprop … lock` → "unknown request"; retry with 0.53 names and a tag rule |
| `hypr-ipc events`: `openwindow`, `closewindow`, `movewindow`, `activewindow` seen | open/close/focus/title yes; **no event for moving or resizing a floating window** | `openwindow>>63b2bc83e780,2,foot,foot`, `closewindow>>63b2bc83e780`, `activewindowv2>>63b2bc7d7f70`, `windowtitlev2>>63b2bc83e780,foot` |
| `hypr-ipc bench 5`: one batch | 0.09–0.14 ms | 10 commands |
| `hypr-ipc bench 5`: separate requests | 1.2–4.0 ms | 10 requests |
| Batched move looks like one step (no visible intermediate positions) | | |
