# M2.11 – Remaining host interface checks

- Date: YYYY-MM-DD
- Host: Ubuntu 26.04 LTS, GNOME, CUPS, Hyprland v0.53.3 nested

## Question

Three leftovers from M2.10: printing through the host's CUPS socket (`print`,
ADR 0019), `SettingChanged` reaching a client in the context, and an inhibit
being released when the calling program exits (one host connection per client).

## Setup

Context a with `KOJE_SPIKE_HOSTBUS=1 KOJE_SPIKE_CUPS=1`, proxy and both
forwarders as in M2.10; `docs/spikes/setup/portal-check.py` as the client.

Design note: with one host connection per client, a client receives portal
signals only after it has called the portal once (that call opens its host
connection). Real apps read the settings first; `gdbus monitor` alone sees
nothing.
